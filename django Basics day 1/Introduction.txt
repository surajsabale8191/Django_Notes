🏢 Project Core Configuration (config/)
This folder contains the master control files for the entire project. 
It acts as the brain that directs incoming web traffic and settings.


settings.py: The most critical file for configuration. It houses database credentials, registered applications, 
middleware, time zones, and static file asset paths.

urls.py: The routing table of your project. 
It maps the URL paths entered into a web browser to the correct code execution blocks (views).


wsgi.py & asgi.py: Entry points for web servers to run your application. 
wsgi handles standard synchronous web traffic, while 
asgi handles modern, asynchronous features like WebSockets.

__init__.py: 
A blank file that tells Python to treat this directory as an importable module package

.__pycache__/: 
Automatically generated folders containing compiled Python bytecode (.pyc).
These help your application load faster and can be safely ignored.

📦 The Custom App (notes/)
Django projects are broken down into small, 
isolated apps to keep code modular. 
This notes folder is where you write the core business logic for your notes feature.

models.py: 
The blueprint for your data structure. 
This is where you write Python classes to define your database tables using the Django ORM we discussed earlier.

views.py: 
Contains the logic that processes incoming HTTP requests, 
interacts with your models to fetch data, and returns the final HTTP response or webpage.

admin.py: 
Used to register your models with Django's built-in, out-of-the-box administration portal interface.

apps.py: 
Contains configuration metadata specific to the notes application itself.

tests.py: 
The dedicated space to write automated test scripts ensuring your application code doesn't break over time.

migrations/: Stores automated tracking files generated by Django. 
Whenever you alter your models.py file, Django saves migration files here to update your actual database schema safely.



⚙️ Root Directory FilesThese files sit outside your source folders to manage execution and environments.

manage.py: 
A command-line utility script. You run this file in your terminal to start the development server (runserver),
 generate database tables (migrate), or create new apps.
 
 db.sqlite3: 
 The actual SQLite database file. 
 It contains all your stored application data during local development.
 
 venv/: Your Virtual Environment folder. 
 It keeps all project dependencies, libraries, 
 and your specific Python version contained so they don't conflict with other projects on your computer.
